# 設計メモ：年間計画タブ（採用活動の予定と実績の年表）

作成日: 2026-10-28　対象: monoloop-mypage 管理画面（React + Vite + Firebase）
デモ（依頼者が承認済み・方向性の基準）: https://claude.ai/artifact/5zJJwdDEvNCZSs6wmcSVQ1

## 1. 目的（なぜ）
毎年どの時期に何をやっていたかを1本の年表で見られるようにし、翌年の採用計画を立てやすくする。使い方は「年の初めに計画を立てる → その後、実施した活動をその場で足していく」が主で、「今月やることの確認」が従。

## 2. ゴール／やらないこと
- ゴール: 卒年度ごとの年表（8月〜翌々年3月の20か月）に、人事が置く活動カード（予定／実施済み／中止）と、システム内の記録から自動で出る実績を並べて見られる。前年度を重ねて比較でき、前年度の予定を今年度にコピーできる。
- やらないこと: 学生への表示（管理者専用）。カードのドラッグ移動（日付はフォームで編集）。ガント以外の表示形式（カレンダー・リストは月リストのみ）。通知・リマインド。開始月や期間の画面からの設定変更（コード定数で持つ）。
- 失敗の定義: 年表の列と日付がずれる（8月始まり・20か月で、暦月の列に正しく置かれないと比較できない）。カードが重なって読めない。スマホで横にはみ出す。

## 3. 年表の軸（決定事項）
- 1本の年表＝1つの卒年度。期間は **卒業年の2年前の8月1日 〜 卒業年の3月31日**（20か月）。例: 2028卒 ＝ 2026-08-01〜2028-03-31。
- 列は暦月（8月, 9月, …, 翌々年3月）。年が変わる列（1月）と先頭列に西暦を小さく添える。
- 前年度を重ねるときは、**同じ月の列に揃える**（2027卒の「10月」は 2028卒の「10月」と同じ縦の列）。暦では1年ずれるが、比較の目的に合わせる。
- 「今月」の列は琥珀色（デモと同じ）。初期表示では今月の列が画面に入る位置まで横スクロールする。
- 開始月（8）と月数（20）は `src/lib/annualPlan.js` の定数 `PLAN_START_MONTH` / `PLAN_MONTHS`。

## 4. 活動カード（人事が置くもの）
### 4.1 項目
| 項目 | 型 | 備考 |
| --- | --- | --- |
| grad | number | 卒年度 |
| kind | "seminar" / "oc" / "select" / "follow" / "media" / "campus" / "other" | 説明会／オープンカンパニー／選考／内定者フォロー／媒体・スカウト／学内・大学／その他 |
| title | string | 必須 |
| start / end | "YYYY-MM-DD" | end は start 以上。1日だけなら同じ日 |
| status | "plan" / "done" / "cancel" | 予定／実施済み／中止 |
| owner | string | 担当者（任意） |
| memo | string | 実施後の記録（任意） |
| createdAt / updatedAt | Timestamp | |

### 4.2 保存先
`templates` コレクションに `_type:"planItem"`（管理者のみ read/write。ルール変更なし・Vercel 関数の追加なし）。AdminApp が常時購読している `savedTemplates` から拾う。`realTemplates`（LINE 配信テンプレ一覧）の除外リストに `planItem` を追加する。

### 4.3 操作
- 追加: 「＋ 活動を追加」→ 右ドロワー（既存の面談記録ドロワーと同じ作り。PC は幅 440px、スマホは全幅）。初期値: 卒年度＝表示中（候補から変更可）、種類＝その他、開始＝終了＝今日、状態＝予定。
- 編集: カード（年表）または行（月リスト）を押す → 同じドロワー。状態は3ボタンで切替。削除は確認つき。
- 色: 種類ごとに固定（デモと同じ。説明会＝青 #4F46E5、OC＝橙 #EA580C ＝特別選考タブの `KIND_STYLE` と同じ値、選考＝マゼンタ（ブランド色）、内定者フォロー＝緑 #059947、媒体＝水色 #0891B2、学内＝紫 #7C3AED、その他＝灰）。予定は破線枠・白地、実施済みは「✓」付き・塗り、中止は取り消し線・半透明。
- 凡例の種類を押すとそのレーンを表示/非表示（状態はページ内のみ）。

### 4.4 前年度の予定をコピー
- 「前年度からコピー」ボタン → 確認モーダル「{前年度}卒の活動 {N}件を {今年度}卒に予定として追加します（日付は1年後ろにずらします）」→ 実行で N 件を `status:"plan"`, `memo:""`, 日付＋1年で追加。中止（cancel）の活動はコピーしない。元の実施済みメモはコピーしない。コピー済みかどうかの判定はしない（2回押せば2重になる。確認文にその旨を書く）。
- 2/29 は 2/28 に丸める。

## 5. 自動で出る実績（既存データ・読み取りのみ）
年表の下側に薄い灰色のレーンとして表示。クリックで元の画面へ（可能なものだけ）。手入力・保存はしない。
| レーン | 元データ | 日付 | 卒年度 | 表示 | クリック |
| --- | --- | --- | --- | --- | --- |
| イベント | events（published） | dateStr | grad | タイトル | 概況タブへ（`setTab("dash")`） |
| アンケート | surveys（published・interview≠true） | dueDate（無ければ createdAt） | grad | タイトル（pulse は「パルス調査：{title}」） | 概況タブへ |
| 記事 | articles（published） | publishAt または createdAt | grad（null＝全年度に出す） | タイトル | 記事タブへ |
| LINE配信 | broadcasts | sentAt | grad | target（配信対象名） | LINE配信タブへ |
| 面談 | templates `_type:"meeting"` | date | grad | 月ごとの件数「N件」 | 面談タブへ |
| 説明会・OC日程 | templates `_type:"specialSlot"` | date | なし（全年度に出す） | 「説明会」「OC」＋時刻 | 特別選考タブへ |
- 「システムの記録も表示」チェックで一括で隠せる（既定オン）。
- 年表の期間外のものは出さない。

## 6. 画面構成（管理画面に新タブ「年間計画」）
- タブ: `{ key: "plan", label: "年間計画", icon: CalendarRange }` を「面談」と「分析」の間に追加（PC サイドバー・スマホ下部タブ両方）。
- **年度の扱い（設計者の判断・レビュー指摘への回答）**: 年間計画タブは**独自の年度 state** を持ち、候補は「cohorts の年度 ∪ planItem に存在する年度 ∪ その最大値＋1」を降順で並べる（内定者がまだいない次の年度の計画を先に立てられるようにする）。このタブでは AdminApp 共通の年度スイッチャーと「学生画面」ボタンを隠す（AdminApp 側に `tab !== "plan"` の条件を1つ足す。二重表示を避けるため）。開いた時の初期値は共通の `selectedYear`。ドロワーの卒年度欄は候補から選べる（編集可）。システムの記録をクリックして他タブへ移るときは、`selectYear(grad)` で共通の年度を揃えてから `setTab` する（別年度の概況に飛ばないため）。props に `selectedYear` と `selectYear` を追加する。
- `broadcasts` は現状 LINE タブを開いたときだけ読み込むので、年間計画タブを開いたときも読み込む（AdminApp の条件に `tab === "plan"` を足す）。
- 年表（PC）と月リスト（スマホ）の切替は画面幅ではなく既存の `pc` prop に従う。
- 上部: 見出し／卒年度の切替（既存の年度スイッチャーと同じ見た目）／「前年度を重ねて表示」チェック／「システムの記録も表示」チェック／「今月へ」／「前年度からコピー」／「＋ 活動を追加」／凡例。
- 年表ボード（卒年度ごとに1枚。重ね表示時は前年度を下に）: 見出し行に「{grad}卒」と「N件 実施済み／M件 予定」。左に固定のレーン名列（種類名＋「実施済み/全件」）、右に20列。レーンの高さはそのレーン内でカードが重ならないよう行数×30px。
- カードの最小表示幅は約1か月分（1日だけの活動でもタイトルが読める）。超過分は省略記号、`title` 属性に全文。
- スマホ（画面幅 < 768px）: 年表の代わりに月ごとの縦リスト（デモと同じ）。今月の枠を強調し「今月」ラベル。
- 空状態: カードが0件なら年表の上に「まだ活動がありません。「＋ 活動を追加」か「前年度からコピー」から始められます。」。

## 7. 実装上の制約・既存の約束事
- 新しい API ファイルは作らない（関数数 11/12）。この機能は API を使わない（すべてクライアントから Firestore 直接。templates は管理者のみ）。
- 純粋ロジック（期間計算・位置計算・行割り当て・日付の1年シフト）は `src/lib/annualPlan.js` に置き、`tests/annualPlan.test.mjs`（node --test）で検証する。
- 画面は `src/components/AnnualPlan.jsx`（新規）。AdminApp.jsx からは props（savedTemplates, events, surveys, articles, broadcasts, cohorts, pc, setBanner, setTab, selectedYear, selectYear）を渡すだけにし、AdminApp.jsx の肥大化を避ける（共通スイッチャーを隠す条件と broadcasts の読み込み条件の2点だけ AdminApp 側に手を入れる）。
- `<input type="date">` をスマホ幅の2列グリッドに入れない。モーダル/ドロワー表示中は `useBodyScrollLock` の条件に追加する（AnnualPlan 内の open 状態を AdminApp に伝える必要があるため、ドロワーの開閉は AnnualPlan 内部で完結させ、`useBodyScrollLock` は AnnualPlan 内で呼ぶ）。
- CLAUDE.md（3章ディレクトリ・4章データモデル・8章完了済み機能・9章）を更新。push は要約提示＋承認後。

## 8. builder に任せること
- レーンの高さ・カードの行間・色の微調整。
- 月リストの並び（今月を先頭にするか、8月から並べるか。既定は8月から・今月に自動スクロール）。
- broadcasts の grad が無い古い記録の扱い（出さない）。
- 「今月へ」のスクロール位置の計算。
- テストの範囲（期間・位置・行割り当て・日付シフトは必須）。
