# 設計メモ：特別選考LPの候補日程／面談記録のスクリーンショット／面談記録の流入経路表示

作成日: 2026-10-27　対象: monoloop-mypage（React + Vite + Firebase + Vercel Serverless）

このメモは3つの独立した変更をまとめたもの。いずれも既存の仕組み（templates コレクション・公開API の action 分岐・image.js の圧縮）の延長で実装し、**Firestore ルール・環境変数・Vercel 関数数（11/12）は変えない**。

---

## 1. 特別選考LP：説明会・オープンカンパニーの候補日程

### 1.1 目的・背景（なぜ）
特別選考ルート①は「説明会」から、②は「オープンカンパニー（OC）」から始まる。現状の LP（`/special`）はルートを選んで連絡先を送るだけで、日程は後からメールで調整している。人事があらかじめ日程を登録し、学生がエントリー時に都合のよい候補を選べるようにして、日程調整のやり取りを減らす。

### 1.2 ゴール／やらないこと
- ゴール: 学生がエントリー時に候補日程に複数印を付けられる。人事が管理画面で日程を登録・停止し、エントリーごとに1つの日程を「確定」できる。OC の枠ごとに「残り○名」を出し、満員の枠は選べない。
- やらないこと: 残り人数の自動計算（**残り人数は人事が手入力**）。学生側からの日程変更・キャンセル。リマインドメールの自動送信。カジュアル面談ルートの日程設問（従来どおり設問なし）。
- 失敗の定義: 学生が候補を1つも選ばず・別日希望もないまま送信できてしまう。満員の枠に印が付けられる。候補が人事に見えない。

### 1.3 学生側（SpecialEntry.jsx）の振る舞い（決定事項）
- ルート①（special1）を選ぶとフォームの**先頭**に「説明会の候補日程」、②（special2）なら「オープンカンパニーの候補日程」の設問を出す。カジュアル面談（casual）には出さない。
- 候補は**チェックボックス**で複数選べる。表示は「10/15（水）14:00〜15:00」。残り人数が登録されている枠は「残り3名」を添える。残り 0 の枠は「満員」と表示し disabled。残り人数が未登録（null）の枠は人数を表示しない。
- 一番下に「候補の中に参加できる日がない（別日で調整を希望）」のチェックを置く。チェックすると直下に「人事から別途ご連絡します」と表示。
- 送信条件（①②のみ）: 候補が1つ以上 **または** 別日希望がチェックされていること。どちらも無ければエラー「候補日程を選ぶか、別日での調整を希望してください。」。
- 候補が1件も公開されていないとき（人事が未登録・全停止）は設問を出さず、代わりに「日程は人事からご連絡します」と1行表示し、送信条件は課さない。
- 完了画面と受付メールに、選んだ候補（または「別日で調整を希望」）を一覧で載せ、「日程は人事からご連絡します」と添える。
- 候補の一覧は公開API（下記 1.5）から取得する。LP を開いた時点のデータなので、送信時にサーバー側で再検証する（停止・満員になっていた枠は黙って除外し、残りが 0 かつ別日希望なしならエラーを返す）。

### 1.4 データ（templates コレクション、ルール変更なし）
- 日程: `templates/{autoId}`
  ```
  { _type: "specialSlot", kind: "seminar" | "oc", date: "YYYY-MM-DD", start: "HH:MM", end: "HH:MM",
    note: "", remaining: number | null, active: true, createdAt }
  ```
  - `kind`: seminar＝説明会（ルート①用）／oc＝オープンカンパニー（ルート②用）。
  - `remaining`: 残り人数。**人事が手入力**。null＝人数を出さない。0＝満員。
  - `note`: 任意（会場・オンライン等の短い補足）。
- エントリー `_type:"specialEntry"` に追加するフィールド:
  ```
  slotIds: string[]          // 学生が印を付けた日程の id（①②のみ。casual は []）
  otherDate: boolean         // 別日で調整を希望
  confirmedSlotId: string|null  // 人事が確定した日程（管理画面で設定）
  confirmedAt: Timestamp|null   // 確定日時
  confirmMailAt: Timestamp|null // 確定メールを送った日時（送っていなければ null）
  ```
  - 再エントリー時は slotIds / otherDate を最新で上書きする。confirmedSlotId は同じルートなら保持、ルート（種別）が変わったら null に戻す（1.6 参照）。

### 1.5 公開API（api/public-cohorts.js に action 追加）
- `action=specialSlots`（未ログイン可）: `{ kind }` を受け取り、`_type:"specialSlot"` かつ `active:true` の枠を date, start 順で返す。返すのは `id, date, start, end, note, remaining` のみ。日付が今日（JST）より前の枠は返さない。
- `action=specialEntry` の拡張: `slotIds[]`, `otherDate` を受け取り、ルートが special1/special2 のときだけ検証する。
  - slotIds の各 id について、存在・`active`・`kind` がルートと一致・`remaining !== 0`・日付が今日以降、を確認し、満たさないものは除外。
  - 除外後に 0 件かつ `otherDate !== true` なら 400「候補日程を選ぶか、別日での調整を希望してください。」。
  - 候補が1件も公開されていない状態（specialSlots が空）で送られてきた場合は、slotIds=[]・otherDate=false のまま受け付ける（1.3 の「設問を出さない」ケース）。
  - casual のときは slotIds=[]、otherDate=false で保存。
- 受付メール（本人）: 「ご希望の候補日程」として各候補を「10/15（水）14:00〜15:00」形式で列挙。別日希望なら「別日での調整を希望」。末尾に「日程は人事からご連絡します。」。管理者通知メールにも同じ一覧を載せる。

### 1.6 管理側（SpecialAdmin.jsx）
- 新しい区画「説明会・オープンカンパニーの日程」（特別コードの区画の下）:
  - 追加フォーム: 種別（説明会／OC）・日付（date 入力。**スマホで隣と重ならないよう縦並び or min-w-0**）・開始/終了（既存の `TimeSelect`）・残り人数（数値・空欄可）・補足。「追加」で `_type:"specialSlot"` を作成。
  - 一覧: 日付順。各行に「種別・日時・補足」「残り○名（手入力欄をその場で編集可）」「希望○名／確定○名」（エントリーの slotIds / confirmedSlotId から集計）「停止／再開」「削除」。削除時は、その枠を候補に持つエントリーがあれば件数を添えて確認する（エントリー側の slotIds からは消さず、表示時に「（削除済みの枠）」と出す）。
- エントリー一覧の各カード:
  - 「候補日程」としてチップで表示（kind のアイコン不要。日時のみ）。別日希望は琥珀色のチップ「別日で調整を希望」。
  - 「確定する日程」プルダウン（**設計者の判断・レビュー指摘への回答**）: 選択肢は「未確定」＋**そのルートの種別（①→seminar、②→oc）の有効な全枠**。学生が印を付けた枠には「（希望）」を添えて上に並べる。これで「別日希望のみ」の学生にもメールで調整した日を確定として記録できる。選ぶと `confirmedSlotId` を更新。確定済みはカード上部に緑の「確定 10/15（水）14:00」バッジ。確定した枠が削除・停止済みなら「（削除済みの枠）」「（停止中）」と表示し、未確定に戻せる。
  - 再エントリーでルートが変わった（種別が変わった、または casual になった）場合は、サーバー側で `confirmedSlotId` を null に戻す。同じルートのままなら保持する。
  - 候補が無く別日希望も無い（casual や設問なし）カードには日程の行を出さない。
- フィルター: 既存のルート／状況／コードに「日程」を追加（特定の枠を候補に持つ、または確定しているエントリーに絞る）。
- CSV: 「候補日程」「別日希望」「確定日程」の3列を追加。

### 1.7 確定時の学生への連絡（決定事項・依頼者の回答「送ります」）
- 人事が「確定する日程」を選ぶと、確定モーダル（小さな確認ダイアログ）を出す。内容: 学生名・確定する日程・「確定後に学生へメールで案内を送る」チェック（**既定オン**）・「確定する」ボタン。
- チェックがオンのときは、**管理者認証つきの API action** で Firestore 更新とメール送信を行う。`api/public-cohorts.js` に `action=specialConfirm`（`requireAdmin` 必須。`{ entryId, slotId | null, sendMail }`）を追加する。新しい API ファイルは作らない（関数数 11 を維持）。
  - サーバー側で entry と slot を読み、`confirmedSlotId` を更新し、`sendMail` なら Resend で本人へ送る。メール失敗時も更新は成功扱いにし、レスポンスの `mailSent:false` を管理画面で「メールは送れませんでした」と表示する。
  - `slotId=null`（未確定に戻す）のときはメールを送らない。
- チェックがオフのときも同じ action を使う（`sendMail:false`）。クライアントから直接 `updateTemplate` はしない（処理を1か所にまとめる）。
- 確定メール文面（本人宛）: 件名「【モノ・ループ】{説明会|オープンカンパニー}の日程が確定しました」。本文に氏名、ルート名、確定日程「10/15（水）14:00〜15:00」、補足（note があれば）、「変更が必要な場合はこのメールに返信してください」、署名。
- 確定と同時に対応状況が「未対応」または「連絡済」なら「日程調整済」に自動で進める（それ以外の状況は変えない）。
- 管理画面の確定後の表示: カードに緑の確定バッジ、メール送信済みなら「案内メール送信済 10/27 14:05」を小さく添える（`confirmMailAt` を保存）。

### 1.8 残り人数の運用（決定事項）
残り人数は自動では増減しない。人事が確定操作をしたら、日程一覧の残り人数を自分で減らす。日程一覧には「確定○名」を出すので照合できる。

## 2. 面談記録のスクリーンショット

### 2.1 目的
Zoom 面談中に学生の様子をスクリーンショットで残し、次回以降の面談や人事間の引き継ぎで顔と記録を結び付けられるようにする。

### 2.2 振る舞い（決定事項）
- 面談記録ドロワー（追加・編集）に「学生の様子（スクリーンショット）」の枠を追加する。
  - **主要な操作は貼り付け**: 枠をクリック（フォーカス）して Ctrl+V。クリップボードの画像を取り込む。
  - 予備: ドラッグ＆ドロップ、「ファイルを選ぶ」ボタン。
  - 1つの記録に **最大2枚**。各サムネイルの「×」で削除。
  - 貼り付け直後に縮小・JPEG 圧縮して state に持ち、「保存」で記録と一緒に Firestore へ保存する（保存前にドロワーを閉じたら破棄）。
- 圧縮: 既存 `src/lib/image.js` の `fileToCompressedDataURL(file, { maxDim: 480, quality: 0.75, maxLen: 70000 })` を使う（長辺 480px・1枚あたり概ね 70KB 以下）。
- **保存場所の判断（設計者の判断・レビュー指摘への回答）**: 画像は面談記録と同じドキュメント（`_type:"meeting"` の `shots`）に入れる。管理画面は `templates` コレクション全件を常時購読しているため、画像が増えるほど管理画面を開くたびの通信量が増える（最大 140KB/記録。100 記録で約 14MB）。別コレクションやサブコレクションに分けるとルールの再デプロイが必要になり、現状の規模（年数十〜百数十件）では見合わないと判断した。**面談記録が数百件を超えて管理画面の表示が重くなったら、専用コレクション `meetingShots`（ルール追加）へ移す**。この閾値を CLAUDE.md の残タスクに書いておく。
- 貼り付けた画像が圧縮後も `maxLen` を超える場合は image.js が品質を段階的に下げる（既存の挙動）。それでも入らなければエラー表示して取り込まない。
- 表示: サムネイル（高さ 72px 程度、正方形トリミング不要・object-fit: cover）を次の場所に出す。タップで元サイズ（640px）をモーダル表示。
  1. 面談履歴モーダル（内定者別カードをタップ）の各記録
  2. 「日付順」一覧の各カード
  3. 内定者詳細の直近3件
  4. 記録ドロワー（編集時に既存の画像が並び、追加・削除できる）
- 学生側マイページには出さない（面談記録は `templates` にあり、学生は読めない。表示側にも載せない）。
- 記録の削除で画像も一緒に消える（同じドキュメント内のため自動）。

### 2.3 データ
- 面談記録 `_type:"meeting"` に追加:
  ```
  shots: string[]   // 圧縮済み dataURL（image/jpeg）。古い記録には無い＝[] 扱い
  ```

## 3. 面談記録の「内定者」表示に流入経路を追加

### 3.1 振る舞い（決定事項）
- 記録ドロワーの「内定者」プルダウンの選択肢を「氏名（大学名 学部）・流入経路」にする。流入経路（`students.source`）が空なら「流入経路 未登録」。
  - 例: `山田 花子（早稲田大学 商学部）・マイナビ`
- 選択後、プルダウンの下に同じ情報を小さく表示する（PC では右カラムの参考情報の上でもよい）。
- 面談履歴モーダルの見出し（氏名の下）にも「大学名 学部・流入経路」を出す。
- 大学名・学部は `students.univ` の1項目に入っている（例「早稲田大学 商学部」）ので分割しない。

## 4. 実装上の制約・既存の約束事（必読）
- Vercel Hobby は関数 12 個まで。**新しい API ファイルは作らない**。日程の取得・検証は `api/public-cohorts.js` の action で行う。
- `templates` コレクションに新しい `_type` を足すときは、LINE 配信テンプレの一覧（AdminApp.jsx の `realTemplates`）から除外する（`specialSlot` を追加）。
- ルート定義は `src/lib/specialRoute.js` と `api/public-cohorts.js` の両方にある。ルートと日程種別の対応（special1→seminar, special2→oc）も両方に持つ。
- `<input type="date">` をスマホ幅の 2 列グリッドに入れない（CLAUDE.md「ハマりどころ」参照）。
- 時刻入力は `TimeSelect`（components/common.jsx）を使う。
- 日付の曜日表示「10/15（水）」は LP・メール・管理画面で共通の小さな関数を用意する（specialRoute.js に置き、API 側は同等の関数を複製）。
- CLAUDE.md（4章データモデル・8章完了済み機能・9章残タスク）を更新する。
- push 前にビルド確認・要約提示・承認（CLAUDE.md 6章）。

## 5. builder に任せること
- 各 UI の細かなレイアウト、文言の微調整、サムネイルの寸法。
- 日程追加フォームのバリデーション文言。
- 日程一覧の並び・折りたたみ（件数が増えたときの見せ方）。
- 画像の上限枚数（既定 4）。
- テストの範囲（ビルド＋API の構文チェックは必須。可能なら API のローカル e2e）。
